# API and Webhooks

> Target design for Phase 3. The OpenAPI document generated by the app (`/openapi.json`) is the source of truth once implemented. Update this file when it differs.

## Overview

- Base path: `/api/v1`
- Format: JSON (`Content-Type: application/json`)
- Auth: `Authorization: Bearer <api_key>`
- Versioning: path-based. Breaking changes require `/api/v2`.
- Time: ISO 8601 UTC (`2026-11-24T09:30:00Z`)
- IDs: tickets are addressed by their human-friendly `number`; other resources by UUID.

## Authentication

API keys are created by admins in Settings → API keys. The full key is shown once.

```http
GET /api/v1/tickets HTTP/1.1
Authorization: Bearer wpt_live_xxxxxxxxxxxxxxxxxxxxxxxx
```

Scopes:

| Scope | Allows |
|---|---|
| `tickets:read` | List and read tickets, messages, customers |
| `tickets:write` | Create tickets, reply, change status, assign |
| `customers:write` | Create and update customers |
| `webhooks:manage` | Manage webhook endpoints |

Errors: `401` for missing or invalid key, `403` for insufficient scope.

## Conventions

### Pagination

Cursor-based.

```http
GET /api/v1/tickets?limit=50&cursor=eyJ...
```

```json
{
  "data": [ ... ],
  "next_cursor": "eyJ...",
  "has_more": true
}
```

`limit` default 25, max 100.

### Errors

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Subject is required.",
    "details": { "field": "subject" }
  }
}
```

| HTTP | `code` | Meaning |
|---|---|---|
| 400 | `bad_request` | Malformed JSON or parameters |
| 401 | `unauthorized` | Missing or invalid API key |
| 403 | `forbidden` | Key lacks scope |
| 404 | `not_found` | Resource does not exist in this workspace |
| 409 | `conflict` | State conflict, e.g. invalid status transition |
| 422 | `validation_failed` | Field-level validation errors |
| 429 | `rate_limited` | Slow down. `Retry-After` header set |
| 500 | `internal` | Unexpected error |

### Idempotency

`POST` endpoints that create resources accept an `Idempotency-Key` header. Repeating the same key within 24 hours returns the original response.

### Rate limits

Default: 600 requests/minute per key. Responses include `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`.

## Endpoints

### Tickets

| Method | Path | Scope | Description |
|---|---|---|---|
| `GET` | `/tickets` | `tickets:read` | List tickets |
| `POST` | `/tickets` | `tickets:write` | Create a ticket |
| `GET` | `/tickets/{number}` | `tickets:read` | Get a ticket |
| `PATCH` | `/tickets/{number}` | `tickets:write` | Update status, priority, assignee, subject |
| `GET` | `/tickets/{number}/messages` | `tickets:read` | List messages |
| `POST` | `/tickets/{number}/messages` | `tickets:write` | Add a reply or internal note |

List filters: `status`, `priority`, `assignee_id` (use `none` for unassigned), `requester_email`, `tag`, `q` (search, Phase 2), `created_after`, `created_before`.

Create ticket:

```http
POST /api/v1/tickets
```

```json
{
  "requester": { "email": "dana@example.com", "name": "Dana" },
  "subject": "Can't log in",
  "message": "I keep getting an error when I sign in.",
  "priority": "normal",
  "mailbox": "help@example.com"
}
```

Add a reply:

```json
{
  "kind": "agent",
  "body_text": "Thanks Dana, try resetting your password.",
  "send_email": true
}
```

`kind: "note"` creates an internal note and never sends email.

Update:

```json
{ "status": "resolved", "assignee_id": "a93b..." }
```

Invalid transitions return `409 conflict`.

| Method | Path | Scope | Description |
|---|---|---|---|
| `GET` | `/webhooks` | `webhooks:manage` | List endpoints |

## Webhook events

| Event | Fired when |
|---|---|
| `ticket.created` | A ticket is created through any channel |
| `ticket.updated` | Subject or priority changes |
| `ticket.assigned` | Assignee changes |
| `ticket.status_changed` | Status changes |
| `message.created` | A customer or agent message is added (not internal notes by default) |

### Payload envelope

```json
{
  "id": "evt_01JD...",
  "type": "ticket.status_changed",
  "created_at": "2026-11-24T10:02:11Z",
  "workspace": "acme",
  "data": {
    "ticket": { "number": 1042, "status": "resolved", "...": "..." },
    "previous": { "status": "open" }
  }
}
```

### Signing

Each delivery includes:

```http
X-Waypoint-Event: ticket.status_changed
X-Waypoint-Delivery: dlv_01JD...
X-Waypoint-Signature: t=1763978531,v1=5257a869e7ecebeda32affa62cdca3fa51cad7e77a0e56ff536d0ce8e108d8bd
```

Compute `HMAC-SHA256(secret, "{t}.{raw_body}")` and compare to `v1` in constant time. Reject if `t` is more than 5 minutes old.

### Delivery and retries

- A `2xx` response within 10 seconds counts as success.
- Otherwise retry with backoff: 1 min, 5 min, 30 min, 2 h, 12 h (5 retries).
- After repeated failures the endpoint is marked disabled and admins are notified.
- Deliveries are **at least once**. Receivers should dedupe on `id`.

## OpenAPI

Topcoat's `openapi` feature generates an OpenAPI 3.1 document from the router, so the spec is derived from the same routes that serve traffic.

How we use it:

- Enable the `openapi` feature and add `schemars`. Derive `schemars::JsonSchema` on API request and response types (see [ADR-008](DECISIONS.md#adr-008-api-types-are-separate-from-domain-types)).
- Put shared settings on a `#[layer("/api", with(Operation::new()...))]`: the `api` tag, a `401` response, and the bearer security reference. Routes under it inherit these.
- Add an `Operation` to each route with summary, request type, and responses. Use `.query::<T>()` for `#[query_params]` structs and `Parameter::path("number").schema::<u64>()` to type path parameters.
- Register the scheme once: `OpenApi::new("Waypoint API", "1.0.0").security_scheme("token", SecurityScheme::bearer())`, and use `Operation::security("token")`. Use `.no_security()` on any public route.
- Mark internal routes (inbound email webhook, public form, health checks) with `Operation::new().hidden(true)`.
- Serve the document at `GET /openapi.json` by returning `OpenApi::...generate(&router(cx))` from a route.
- In CI, write the document with `Document::to_json_pretty` and diff it against a committed `openapi.json` to catch accidental breaking changes.

Caveats from Topcoat's docs: operations are not checked against handler signatures, and security settings only describe authentication. The `/api` layer and the handlers must still enforce it. `generate` panics on an unknown path parameter or security scheme, which makes it a good startup or CI check.

## Internal (non-public) endpoints

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/webhooks/inbound/email` | Inbound email provider webhook. Authenticated with `INBOUND_EMAIL_SECRET`. Raises the body limit. Hidden from OpenAPI |
| `POST` | `/support/new` | Public web form submission. Rate limited, honeypot protected |
| `GET` | `/healthz`, `/readyz` | Liveness and readiness |

Topcoat's default `OriginPolicy` rejects cross-origin mutations before layers run. That is the right default for the cookie-authenticated UI. Server-to-server endpoints authenticated by a bearer token or shared secret (`/api/*`, `/webhooks/*`) should disable it **only on those routes** (via a layer on their path) and authenticate explicitly. Verify how the policy treats requests with no `Origin` header before relying on the default for them.
